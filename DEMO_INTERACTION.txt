# Medical RAG System - Demo Interaction

This file shows what a typical interaction with the system looks like.

================================================================================
SCENARIO: User asks about diabetes
================================================================================

USER INPUT:
-----------
"What is diabetes?"

SYSTEM PROCESSING:
------------------
1. Frontend sends request to backend API:
   POST http://localhost:8000/ask
   {
     "question": "What is diabetes?",
     "top_k": 5,
     "use_kg": true
   }

2. Backend RAG System:
   a) Optionally expands query using Knowledge Graph
      - Searches KG for "diabetes" entity
      - Finds related terms (Type 2 diabetes, insulin, etc.)
   
   b) Retrieves relevant documents from Vector Database
      - Generates query embedding
      - Searches FAISS index for top 5 similar documents
      - Returns documents with similarity scores
   
   c) Generates answer using Gemini
      - Constructs prompt with retrieved context
      - Calls Gemini API with temperature=0.3
      - Receives generated answer
   
   d) Calculates confidence score
      - Based on retrieval scores
      - Based on number of relevant documents
      - Returns value between 0.0 and 1.0

3. Backend returns structured response:
   {
     "answer": "Diabetes is a chronic health condition that affects how 
                your body turns food into energy. Most of the food you eat 
                is broken down into sugar (glucose) and released into your 
                bloodstream. When your blood sugar goes up, it signals your 
                pancreas to release insulin. Insulin acts like a key to let 
                the blood sugar into your body's cells for use as energy.
                
                ⚠️ Medical Disclaimer: This information is for educational 
                purposes only. Always consult healthcare professionals for 
                medical advice.",
     
     "sources": [
       {
         "id": 0,
         "text": "Diabetes is a chronic health condition...",
         "score": 0.89,
         "metadata": {
           "category": "disease",
           "source": "medical_textbook",
           "question": "What is diabetes?"
         }
       },
       {
         "id": 3,
         "text": "Type 2 diabetes is typically treated with...",
         "score": 0.76,
         "metadata": {
           "category": "treatment",
           "source": "clinical_guidelines"
         }
       }
     ],
     
     "confidence": 0.85,
     "query": "What is diabetes?",
     "retrieved_docs": 5
   }

================================================================================
PERFORMANCE METRICS:
================================================================================

Query Processing Time: ~2 seconds
  - Query expansion: 50ms
  - Vector search: 100ms
  - Gemini generation: 1500ms
  - Response formatting: 50ms

Memory Usage:
  - FAISS index: ~5MB (15 documents)
  - Neo4j: ~50MB (12 entities, 8 relationships)
  - Application: ~200MB

API Request/Response Size:
  - Request: ~100 bytes
  - Response: ~2KB

================================================================================
KNOWLEDGE GRAPH QUERY EXAMPLE:
================================================================================

When the user asks about "aspirin", the system:

1. Searches KG for "aspirin" entity
2. Finds related entities:
   - TREATS → headache (Symptom)
   - TREATS → fever (Symptom)  
   - SIMILAR_TO → ibuprofen (Drug)

3. Expands query: "aspirin headache fever pain relief"

4. Gets better retrieval results due to expanded query

================================================================================
ALTERNATIVE SCENARIOS:
================================================================================

SCENARIO: Gemini API Not Available
------------------------------------
System gracefully degrades:
- Uses retrieval-only mode
- Returns top document as answer
- Includes note: "Using retrieval only (no LLM generation)"
- Confidence score adjusted lower

SCENARIO: Neo4j Not Available
------------------------------
System continues without KG:
- Skips query expansion
- Uses direct vector search only
- Still provides accurate answers
- Confidence scores based only on retrieval

SCENARIO: No Relevant Documents Found
--------------------------------------
System response:
"I couldn't find relevant information to answer your question. 
Please try rephrasing or ask a different medical question."
- Confidence: 0.0
- Sources: []
